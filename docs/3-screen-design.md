## 3. 공통 요소

- **앱 이름**: 화면에 보이는 앱 이름(로고, 로그인 카드 제목, 앱 시작 화면)은 `Badminatics`다.
- **상단 메뉴**: `캘린더` · `참석 현황` · `내 정보` · (ADMIN만) `회원 관리` · `그룹 관리` · `채팅 보관함` · `로그아웃`
  - 데스크톱 상단 바: 로고 `Badminatics` → 메뉴 → 오른쪽에 로그인 정보 `(이메일:로그인중:관리자)` 또는 `(이메일:로그인중:사용자)`, 언어 선택, [로그아웃].
  - 모바일 상단 바: ≡(SCR-04는 ←) + 지금 화면 이름 + 오른쪽 언어 선택. 로고·로그인 정보·[로그아웃]은 숨기고, 로그아웃은 ≡로 여는 메뉴 서랍에 둔다.
- **언어 선택**: `한국어` · `English` · `中文`. 상단 바와 SCR-01·SCR-02 오른쪽 위에 있다. 처음 값은 이 브라우저에 저장해 둔 값, 없으면 브라우저 언어(한국어·중국어), 그 밖에는 English다. 고르면 이 브라우저에 저장한다(PRD FR-23, S-19). 날짜·요일 표기도 고른 언어를 따르고, 서버가 주는 `기본`·`탈퇴 회원`도 고른 언어로 바꿔 보여 준다.
- **접근 제어**: 로그인하지 않았으면 모든 화면에서 SCR-01로 보낸다(R-1). 관리자 메뉴와 관리자 화면은 `ADMIN`에게만 보인다(R-8).
- **로그인 유지**: 앱을 열거나 새로고침하면 먼저 로그인 상태를 되살리고, 성공하면 보던 화면을, 실패하면 SCR-01을 보여 준다. 로그인 연장은 화면에 드러나지 않는다(PRD 6.1 흐름 3·6, S-14).
- **강제 로그아웃**: 회원 삭제, 비밀번호 변경, 도용 의심으로 로그인이 끊기면 어느 화면에서든 SCR-01로 보내고 "다시 로그인해 주세요"를 표시한다(PRD D-4 `UNAUTHENTICATED`, S-15).
- **그룹 상태 배지**: `참석가능 (n/정원)` 또는 `참석완료 (n/정원)` (R-5). 지난 날짜에서 정원이 차지 않은 그룹은 `참석불가 (n/정원)`(R-5, R-6)
- **생년월일 표시**: `1974년11월14일(52세)`. 나이는 `현재연도 - 출생연도`로 계산한다.
- **날짜 기준**: 캘린더의 "오늘", 날짜 비교, 나이 계산은 모두 한국 시간(Asia/Seoul) 기준이다(R-12).
- **탈퇴 회원 표시**: 삭제된 회원이 남긴 기록(지난 참석 기록, 그 회원이 만든 그룹의 만든 사람)은 관리자가 아닌 회원에게 이름 대신 `탈퇴 회원`으로 표시한다. 관리자에게는 SCR-04, SCR-06, SCR-08, SCR-09 등 어느 화면이든 실명 옆에 `(탈퇴)`를 붙여 보여 준다(R-9).

## SCR-01. 로그인

```
┌─────────────────────────────┐
│                [한국어 ▼]   │
│         Badminatics         │
│  이메일    [              ] │
│  비밀번호  [              ] │
│  [ 로그인 ]                 │
│  계정이 없나요? 가입하기    │
└─────────────────────────────┘
```

| 요소 | 설명 |
|------|------|
| 이메일, 비밀번호 | 필수 |
| 로그인 | 성공하면 SCR-03으로 이동 |
| 가입하기 | SCR-02로 이동 |
| 언어 선택 | 오른쪽 위. 공통 요소 참고 |

- 이메일이 비어 있거나 형식이 틀리면 이메일 칸 아래에 "올바른 이메일 형식이 아닙니다", 비밀번호가 비어 있으면 비밀번호 칸 아래에 "비밀번호를 입력해 주세요"를 표시한다(400 `VALIDATION_ERROR`, PRD 9장).
- 로그인에 실패하면 [로그인] 버튼 바로 위에 "이메일 또는 비밀번호가 올바르지 않습니다"를 표시한다. 삭제된 회원이 로그인해도 같은 메시지를 표시한다(R-1). 제출 중에는 버튼 글자가 `로그인 중…`으로 바뀐다.
- (PRD FR-18, 구현됨) 같은 이메일로 15분 안에 5번 실패하면 15분 동안 로그인을 막고 "로그인 시도가 너무 많습니다. 15분 후 다시 시도해 주세요"를 표시한다(429 `TOO_MANY_ATTEMPTS`). 이 문구도 [로그인] 버튼 바로 위에 보인다.

## SCR-02. 회원가입

```
┌─────────────────────────────────────┐
│ 회원가입                            │
│ 이름      [                ]        │
│ 이메일    [                ]        │
│ 비밀번호  [                ]        │
│ 전화번호  [                ]        │
│ 생년월일  [ 1990-03-02 📅 ] (36세)  │
│ [ 가입 ]  [ 취소 ]                  │
└─────────────────────────────────────┘
```

| 요소 | 검증 |
|------|------|
| 이름 | 필수 |
| 이메일 | 필수, 이메일 형식, 활성 회원 사이에서 중복 불가. 삭제된 회원의 이메일은 다시 쓸 수 있다(R-9) |
| 비밀번호 | 필수, 8자 이상(최대 72바이트, PRD NFR-10) |
| 전화번호 | 필수, `01X-XXX(X)-XXXX` 형식(하이픈 생략 가능, 숫자 10~11자리) |
| 생년월일 | 필수, 날짜 선택, 미래 날짜 불가. 옆에 나이가 자동으로 표시된다 |

- 오류 메시지: "올바른 이메일 형식이 아닙니다", "이미 사용 중인 이메일입니다", "올바른 전화번호 형식이 아닙니다", "비밀번호는 8자 이상이어야 합니다", "이름을 입력해 주세요", "생년월일을 선택해 주세요", "올바른 날짜가 아닙니다"(생년월일이 미래이거나 형식 오류), "비밀번호가 너무 깁니다"(72바이트 초과)
- 가입에 성공하면 SCR-01로 이동한다. 역할은 `MEMBER`로 정해진다.

```
│ ◀  2026년 10월  ▶                                          [오늘]   │
├─────────┬─────────┬─────────┬─────────┬─────────┬─────────┬─────────┤
│ 일      │ 월      │ 화      │ 수      │ 목      │ 금      │ 토      │
│         │         │         │         │ 1       │ 2       │ 3 ✔     │
│         │         │         │         │         │         │ 토요복… │
│         │         │         │         │         │         │ 기본(2) │
│ 4       │ 5       │ ...     │         │         │         │         │
│         │ 기본(1) │         │         │         │         │         │
└─────────┴─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘
 그룹명(n) = 그룹과 참여 인원 · ✔ = 내가 참석한 날

 그룹 채팅
 [10/3(토) 토요복식] [10/10(토) 연습A]      ← 이 달에 참석한 그룹마다 탭
┌─────────────────────────────────────────────────────────────────────┐
│ 정하늘 · 10. 2. 오후 08:10                                          │
│ (토요일 7시에 코트 A에서 봐요)                                      │
│                                          이지은 · 10. 2. 오후 08:15 │
│                                                       (네 갈게요)   │
├─────────────────────────────────────────────────────────────────────┤
│ [메시지를 입력하거나 이미지를 붙여넣으세요              ]  [ 전송 ] │
└─────────────────────────────────────────────────────────────────────┘
```

| 요소 | 설명 |
|------|------|
| ◀ ▶ / 오늘 | 월 이동 / 이번 달로 이동. 주소의 월 값이 틀리면 이번 달을 보여 준다 |
| 날짜 칸 | 누르면 SCR-04로 이동. 지난 날짜도 누를 수 있다(R-6) |
| 그룹명(n), ✔ | 그날의 그룹마다 한 줄씩 `그룹명(참여 인원)`. 칸 폭을 넘으면 말줄임(…)하고, 칸 높이를 넘는 그룹은 잘린다. ✔(내가 참석한 날)는 날짜 숫자 바로 옆에 둔다 |
| 범례 | 캘린더 아래 "그룹명(n) = 그룹과 참여 인원 · ✔ = 내가 참석한 날" |

- 캘린더는 3초마다 다시 읽어 다른 회원의 참석을 반영한다.

### 그룹 채팅 구역 (R-14, S-16)

캘린더 아래에 `그룹 채팅` 제목으로 이어진다. 그 그룹에 지금 참석 중인 회원만 읽고 쓴다(관리자도 참석하지 않으면 쓸 수 없다).

| 요소 | 설명 |
|------|------|
| 탭 | 보고 있는 달에 내가 참석한 그룹마다 하나, `10/3(토) 토요복식` 모양. 고른 탭은 주 버튼 색이고, 처음에는 첫 탭을 고른다. 참석을 취소하면 그 탭은 사라진다 |
| 메시지 목록 | 높이를 정해 두고 스크롤한다. 최근 100개를 3초마다 다시 읽고, 새 메시지가 오면 맨 아래로 내린다. 메시지 위에 `이름 · 시각`, 내 메시지는 오른쪽에 옅은 보라 말풍선으로 보인다. 탈퇴 회원 표시는 공통 요소와 같다 |
| 복사 | 글 메시지를 마우스 오른쪽 버튼(모바일은 길게 누르기)으로 누르면 클립보드에 복사하고 "복사했습니다", 실패하면 "복사하지 못했습니다"를 토스트로 알린다 |
| 이미지 보내기 | 입력 칸에 붙여넣기로만 보낸다(파일 선택 버튼 없음). 붙여넣으면 입력 칸 위에 미리보기와 ✕(빼기)가 보인다. PNG·JPEG·GIF·WEBP가 아니면 토스트로 "PNG·JPEG·GIF·WEBP 이미지만 올릴 수 있습니다"를 알린다 |
| 받은 이미지 | 더블클릭하면 크게 본다(바깥을 누르거나 Esc로 닫는다). 마우스 오른쪽 버튼을 누르면 확인 창(제목 `이미지 내려받기`, "이미지를 내려받을까요? (chat-{메시지 번호}.{확장자})", [내려받기]·[취소])을 거쳐 내려받는다. 불러오지 못하면 "이미지를 불러오지 못했습니다" |
| 입력 칸, [전송] | 최대 500자, 안내 문구 "메시지를 입력하거나 이미지를 붙여넣으세요". 이미지와 글이 함께 있으면 이미지를 먼저 보내고 글을 이어서 보낸다. [전송]은 보내는 중이거나 글과 이미지가 모두 비어 있으면 누를 수 없다. 실패는 토스트로 알린다 |

- 이 달에 참석한 그룹이 없으면 "이 달에 참석한 그룹이 없습니다. 날짜를 눌러 그룹에 참석해 보세요"를, 대화방에 메시지가 없으면 "첫 메시지를 남겨 보세요"를 표시한다.
- 그룹이 삭제되면 메시지는 채팅 보관함(SCR-10)으로 옮겨진다(R-15).

## SCR-04. 날짜 상세

```
┌────────────────────────────────────────────┐
│ 2026년 10월 3일 (토)                       │
│ [ + 그룹 만들기 ]      [ 그룹 없이 참석 ]  │
├────────────────────────────────────────────┤
│ 토요복식   참석가능 (3/4)       [ 참석 ]   │
│   김민수, 이지은, 최OO                     │
│ 기본       참석완료 (2/2)       (마감)     │
│   박OO, 정OO                               │
│ 저녁단식 ✔ 참석가능 (1/2)   [ 참석 취소 ]  │  ← 내가 참석한 그룹
│   나                                       │
└────────────────────────────────────────────┘
```

| 요소 | 동작 |
|------|------|
| 그룹 만들기 | SCR-05를 연다. 지난 날짜면 흐리게 표시하고, 누르면 토스트로 "지난 날짜에는 그룹을 만들 수 없습니다"를 알린다(R-6) |
| 그룹 없이 참석 | `기본` 그룹에 참석한다. 지난 날짜면 흐리게 표시하고, 누르면 토스트로 "지난 날짜에는 참석할 수 없습니다"를 알린다(R-6). `기본` 그룹이 없으면 SCR-05를 이름 `기본`으로 고정하고 "만든 뒤 바로 참석"을 켠 채 잠가서 열어, 정원만 고르게 한다(R-2, S-5). 이때 SCR-05는 그룹 생성 API가 아니라 참석 API로 `기본` 그룹을 만들고 참석한다. 그 사이 다른 회원이 `기본` 그룹을 먼저 만들었으면 그 그룹에 그대로 들어간다. 반대로 화면을 연 사이 `기본` 그룹이 삭제되어 정원 값이 필요하다는 응답(400 `VALIDATION_ERROR`)이 오면 SCR-05를 `기본` 모드로 다시 열어 정원을 고르게 한다(PRD 9장). `기본` 그룹이 정원에 찼으면 버튼을 흐리게 표시하되 누를 수 있게 두고, 누르면 토스트로 "정원이 가득 찼습니다"를 알린다(R-3) |
| 참석 | 해당 그룹에 참석을 등록한다. 지난 날짜면 흐리게 표시하고, 누르면 토스트로 "지난 날짜에는 참석할 수 없습니다"를 알린다(R-6) |
| 참석 취소 | 내가 참석한 그룹에만 보인다. 지난 날짜에도 취소할 수 있다(R-6). 내가 마지막 참석자면 아래 확인 창을 먼저 띄운다(R-16) |
| 그룹 카드 | 그룹명(내가 참석한 그룹이면 옆에 ✔), 상태 배지, 참석자 이름. 데스크톱도 카드로 보인다 |
| [편집]·[삭제] (관리자만) | 카드 아랫줄 왼쪽에 보이고, 동작 버튼([참석]·[참석 취소]·`(마감)`)은 오른쪽에 둔다. [편집]은 SCR-09와 같은 편집 패널(그룹명, 정원, 참석자 빼기)을 열고, [삭제]는 SCR-09와 같은 확인 창을 거쳐 그룹을 삭제한다. 날짜와 관계없이 쓸 수 있다(R-8, R-13, PRD D-7). 삭제에 실패하면 확인 창을 닫고 토스트로 알린다 |

- 정원이 찬 그룹은 [참석] 대신 `(마감)`을 표시한다(R-3).
- 관리자가 그룹을 삭제하면(이 화면의 [삭제] 또는 SCR-09) 그 그룹은 목록에서 사라지고, 참석자였던 회원은 그 날짜에 참석하지 않은 상태로 돌아간다(R-13). 그 그룹의 채팅은 채팅 보관함(SCR-10)으로 옮겨진다(R-15).
- 그날 이미 참석한 그룹이 있으면 다른 그룹의 [참석]과 [그룹 없이 참석]은 흐리게 표시하되 누를 수 있게 두고, 누르면 토스트로 "해당 날짜에 이미 참석한 그룹이 있습니다"를 알린다(R-4). [그룹 만들기]는 쓸 수 있지만 SCR-05에서 "만든 뒤 바로 참석"이 해제된 채 잠긴다(R-2).
- 흐린 버튼을 누를 때 이유가 여럿이면 지난 날짜(R-6) → 이미 참석(R-4) → 정원 참(R-3) 순서로 하나만 알린다.
- **지난 날짜**(R-6): 조회와 [참석 취소]만 할 수 있다. [+ 그룹 만들기]·[그룹 없이 참석]·[참석]은 흐리게 표시하고, 정원이 차지 않은 그룹의 배지는 `참석불가 (n/정원)`로 보인다. 관리자의 [편집]·[삭제]는 그대로 쓴다.
- **마지막 참석자의 참석 취소**(R-16, S-17): 그룹의 참석자가 나 한 명일 때 [참석 취소]를 누르면 확인 창(제목 `참석 취소`, "참석을 취소하면 '{그룹명}' 그룹에 참석자가 없습니다. 그룹을 삭제할까요, 남길까요?", 버튼 [삭제]·[남기기])을 띄운다. 만든 사람이나 관리자가 아니어도 고를 수 있다.
  - [삭제]: 참석을 취소하고 그룹을 삭제한 뒤 "그룹을 삭제했습니다"를 알린다. 그 사이 다른 회원이 참석했으면 그룹을 남기고 "다른 참석자가 있어 그룹을 남겨 둡니다"를 알린다. 삭제된 그룹의 채팅은 채팅 보관함으로 옮겨진다(R-15).
  - [남기기]: 참석만 취소한다. 관리자에게는 "그룹을 남겨 둡니다. 나중에 [삭제] 버튼으로 지울 수 있습니다", 그 밖의 회원에게는 "그룹을 남겨 둡니다. 나중에 삭제하려면 관리자에게 요청해 주세요"를 알린다.

## SCR-05. 그룹 만들기 (모달)

```
┌──────────────────────────────┐
│ 그룹 만들기 · 10월 3일 (토)  │
│ 그룹명  [ 토요복식       ]   │
│ 정원    ( ) 2명 단식         │
│         (●) 4명 복식/혼복    │
│ [✔] 만든 뒤 바로 참석        │
│ [ 만들기 ]  [ 취소 ]         │
└──────────────────────────────┘
```

| 요소 | 검증 |
|------|------|
| 그룹명 | 필수, 같은 날짜 안에서 중복 불가. `기본`은 쓸 수 없다(R-2. `기본` 모드는 참석 API를 쓰므로 예외) |
| 정원 | 필수, 2 또는 4. 처음 값은 4 |
| 만든 뒤 바로 참석 | 그날 참석하지 않았으면 선택된 채 열린다. 선택하면 만든 사람을 첫 참석자로 등록하고, 해제하면 그룹만 만든다(R-2, S-12). 그날 이미 다른 그룹에 참석 중이면 해제된 채 잠긴다(R-4) |
| 만들기 | 그룹을 만든 뒤 SCR-04로 돌아간다 |

- 같은 이름의 그룹이 있으면 그룹명 칸 아래에 "같은 날짜에 같은 이름의 그룹이 있습니다"를 표시한다.
- 그룹명이 `기본`이면 그룹명 칸 아래에 "'기본'은 그룹 이름으로 쓸 수 없습니다"를 표시한다(400 `VALIDATION_ERROR`, `field: name`).
- 그 밖의 거부(예: `ALREADY_ATTENDING`)는 모달을 닫지 않고 토스트로 알린다.
- 지난 날짜에서는 열리지 않는다. SCR-04의 [+ 그룹 만들기]가 토스트로 이유를 알린다(R-6, 409 `PAST_DATE`).

## SCR-06. 참석 현황 조회

```
┌──────────────────────────────────────────────────────┐
│ 기간 [2026-10-01]~[2026-10-07]  그룹명 [        ]    │
│ 참석자 이름 [ 이지 ]                                 │
│ 상태 (●)전체 ( )참석가능 ( )참석완료  정원 [전체 ▼]  │
│                                          [ 조회 ]    │
├──────────┬──────────┬──────┬─────────────┬───────────┤
│ 날짜     │ 그룹명   │ 정원 │ 상태        │ 참석자    │
│ 10/3(토) │ 토요복식 │ 4    │ 참석가능 3/4│ 김민수, … │
│ 10/5(월) │ 기본     │ 2    │ 참석완료 2/2│ 이지은, … │
└──────────┴──────────┴──────┴─────────────┴───────────┘
```

| 필터 | 조건 |
|------|------|
| 기간, 그룹명 | 날짜 범위, 그룹명. 처음 열면 기간에 이번 달(Asia/Seoul) 1일~말일이 채워져 있다. 기간은 최대 93일이다(PRD 9장). 넘으면 기간 칸 아래에 "조회 기간은 최대 93일입니다"를, 종료일이 시작일보다 앞서면 "종료일은 시작일보다 앞설 수 없습니다"를 표시한다(`VALIDATION_ERROR` `field: to`) |
| 참석자 이름 | 부분 일치. 관리자가 아닌 회원이 검색하면 탈퇴 회원의 기록은 실명으로 걸리지 않는다(R-9) |
| 상태 + 정원 | `참석가능` + 2인/4인 → 자리가 남은 그룹(지난 날짜의 그룹은 빠진다) / `참석완료` → 정원이 찬 그룹과 참석자 목록(지난 날짜 포함) (R-5) |

- [조회]를 누르면 비어 있지 않은 필터를 주소(URL)에 담는다. 뒤로 가기·새로고침을 해도 같은 결과와 입력 값이 남는다.
- 모바일에서는 필터를 접어 두고 요약 줄 `필터: 10/1~10/31 · 그룹명 · 이름 ▼`(기간, 입력한 그룹명·참석자 이름. 상태·정원은 넣지 않는다)을 보여 준다. 누르면 펼쳐지고 [조회]를 누르면 다시 접힌다. 데스크톱은 늘 펼쳐 둔다.
- 결과가 없으면 "조건에 맞는 참석 기록이 없습니다"를 표시한다. 지난 날짜에서 정원이 차지 않은 그룹은 배지가 `참석불가 (n/정원)`로 보인다(공통 요소).
- 지난 날짜도 조회할 수 있다(R-7). 삭제된 회원은 참석자 목록에 `탈퇴 회원`으로 보인다. 관리자에게는 실명과 `(탈퇴)`로 보인다(R-9).
- 행을 누르면 그 날짜의 SCR-04로 이동한다.

## SCR-07. 내 정보

```
┌─────────────────────────────────────┐
│ 내 정보                  역할: 회원 │
│ 이름      [ 김민수           ]      │
│ 이메일    [ minsu@example.com ]     │
│ 전화번호  [ 010-0000-0000    ]      │
│ 생년월일  [ 1974-11-14 📅 ]         │
│           1974년11월14일(52세)      │
│ 비밀번호 변경 (바꿀 때만 입력)      │
│ 현재 비밀번호 [                ]    │
│ 새 비밀번호   [                ]    │
│ [ 저장 ]                            │
└─────────────────────────────────────┘
```

- 역할은 `역할: 회원`·`역할: 관리자`·`역할: 영구 관리자`로 보기만 할 수 있고 바꿀 수 없다(R-10, R-11).
- 이메일을 바꿀 때 다른 활성 회원이 쓰는 이메일이면 거부한다.
- [저장]은 바뀐 칸만 보내고, 성공하면 토스트로 "저장했습니다"를 알린다.
- 비밀번호는 새 비밀번호를 입력했을 때만 바꾸며, 이때 현재 비밀번호를 입력해야 한다(비우면 현재 비밀번호 칸 아래 "비밀번호를 입력해 주세요"). 저장하면 "저장했습니다" 대신 "다른 기기에서는 로그아웃됩니다"를 알리고 두 비밀번호 칸을 비운다. 이 기기의 로그인은 유지한다(PRD 6.1 흐름 8, S-15).
- 영구 관리자는 이 화면에서 초기 비밀번호를 바꾼다(S-11).
- 오류 메시지: "현재 비밀번호가 올바르지 않습니다"(현재 비밀번호 칸 아래, `WRONG_PASSWORD`), "이미 사용 중인 이메일입니다"(이메일 칸 아래, `EMAIL_TAKEN`), "비밀번호는 8자 이상이어야 합니다"(새 비밀번호 칸 아래), "이름을 입력해 주세요", "생년월일을 선택해 주세요", "올바른 날짜가 아닙니다"(생년월일이 미래이거나 형식 오류), "비밀번호가 너무 깁니다"(새 비밀번호 72바이트 초과), 그 밖의 형식 오류는 SCR-02와 같은 문구

## SCR-08. 회원 관리 (관리자)

```
┌─────────────────────────────────────────────────────────────────────┐
│ 회원 관리  [ ] 삭제된 회원 보기   [ 이름·이메일 ] [ 검색 ]          │
├────────┬───────────────────┬───────────────┬────────┬───────────────┤
│ 이름   │ 이메일            │ 전화번호      │ 역할   │               │
│ 시스템 │ admin@…           │ …             │ 영구   │ [편집]        │
│ 박관리 │ park@…            │ …             │ 관리자 │ [편집] [삭제] │
│ 김민수 │ minsu@…           │ …             │ 회원   │ [편집] [삭제] │
└────────┴───────────────────┴───────────────┴────────┴───────────────┘

[편집] 패널
  이름 / 이메일 / 전화번호 / 생년월일   ← 영구 관리자는 이메일 잠김
  새 비밀번호 [            ]  (비워 두면 바꾸지 않음) ← 영구 관리자·관리자 본인은 잠김
  역할  [ 회원 | 관리자 ]           ← 세그먼트 선택. 영구 관리자는 글자 `영구 관리자`로 잠김
  [ 저장 ]  [ 취소 ]
```

| 요소 | 동작 |
|------|------|
| 검색 | 이름 또는 이메일 부분 일치(PRD FR-19). [검색]을 누르면 앞뒤 공백을 빼고 찾고, 비우고 누르면 전체를 보여 준다. 결과가 없으면 "조건에 맞는 회원이 없습니다" |
| 삭제된 회원 보기 | 켜면 삭제된 회원도 목록 맨 아래에 흐린 글씨로, 실명과 `(탈퇴)` 표시로 보인다. 삭제된 회원 행에는 [보기]만 있고, 같은 패널을 모든 칸 잠김 상태로 연다. 제목은 `회원 보기 · 최민호(탈퇴)`, 버튼은 [닫기] 하나다(R-9) |
| 편집 | 가입 정보와 역할을 수정한다(R-8, R-10). 영구 관리자는 이름·전화번호·생년월일만 수정할 수 있고, 이메일과 새 비밀번호 칸은 잠겨 있다(R-11). 영구 관리자 본인도 이 화면에서는 잠겨 있으며, 이메일과 비밀번호는 SCR-07 내 정보에서 바꾼다 |
| 새 비밀번호 | 관리자가 회원의 새 비밀번호를 지정한다. 현재 비밀번호는 묻지 않고, 기존 비밀번호는 보여 주지 않는다. 비워 두고 저장하면 비밀번호를 바꾸지 않는다(R-8, S-9). 관리자 본인 행에서는 잠겨 있고, 본인 비밀번호는 SCR-07에서만 바꾼다(PRD 6.1 흐름 8) |
| 역할 | `회원`·`관리자` 중 하나를 고르는 세그먼트 선택. 자기 역할도 해제할 수 있다(R-10). 영구 관리자는 선택 대신 글자 `영구 관리자`로 잠겨 있다(R-11). 목록의 역할 열은 `영구`·`관리자`·`회원`으로 보인다 |
| 삭제 | 확인 창("오늘을 포함한 이후의 참석 기록은 삭제되고, 회원 정보와 지난 기록은 남습니다")을 거친 뒤 회원을 비활성화한다(R-9). 삭제된 회원은 기본적으로 목록에서 숨긴다. 영구 관리자 행과 관리자 본인 행에는 삭제 버튼이 없다(R-9, R-11) |

## SCR-09. 그룹 관리 (관리자)

```
┌───────────────────────────────────────────────────────────────┐
│ 그룹 관리    기간 [2026-10-01]~[2026-10-31]   [ 조회 ]        │
├──────────┬──────────┬──────┬──────┬───────────┬───────────────┤
│ 날짜     │ 그룹명   │ 정원 │ 인원 │ 만든 사람 │               │
│ 10/3(토) │ 토요복식 │ 4    │ 3    │ 김민수    │ [편집] [삭제] │
└──────────┴──────────┴──────┴──────┴───────────┴───────────────┘

[편집] 패널
  그룹명 [ 토요단식 ]   정원 ( ) 2명 (●) 4명
  참석자  김민수 [빼기]  이지은 [빼기]  최OO [빼기]
  [ 저장 ]  [ 취소 ]
```

| 요소 | 동작 |
|------|------|
| 그룹명 | 같은 날짜 안에서 중복 불가. `기본`으로 바꾸면 "'기본'은 그룹 이름으로 쓸 수 없습니다"를 표시한다. `기본` 그룹이면 그룹명 칸이 잠기며, 서버도 "'기본' 그룹의 이름은 바꿀 수 없습니다"로 거부한다(R-2, 400 `VALIDATION_ERROR` `field: name`) |
| 정원 | 2 또는 4. 현재 인원보다 작게 바꾸면 "현재 참석 인원보다 정원을 작게 할 수 없습니다"를 표시한다(R-3, S-8) |
| 빼기 | 누르는 즉시 확인 창 없이 해당 참석자의 참석 기록을 삭제해 인원을 정리한다. [저장]과 관계없이 바로 반영된다. 잘못 뺐다면 그 회원이 다시 참석을 등록하면 된다(R-7, R-8, S-8) |
| 삭제 | 확인 창("그룹을 삭제하면 참석자 n명의 참석 기록이 모두 삭제됩니다. 채팅 내용은 채팅 보관함에 남습니다")을 거친 뒤 그룹과 참석 기록을 모두 삭제한다. 참석자들은 그 날짜에 참석하지 않은 상태로 돌아가고, 그룹의 채팅은 SCR-10으로 옮겨진다(R-13, R-15, S-13). 실패하면 확인 창을 닫고 토스트로 알린다 |

- 관리자 메뉴 `그룹 관리`로 들어간다(PRD FR-17). 처음에는 이번 달(Asia/Seoul) 1일~말일을 조회하고, 조회한 기간은 주소(URL)에 남는다.
- 기간이 93일을 넘으면 [조회] 옆에 `! 조회 기간은 최대 93일입니다`를 표시한다(`VALIDATION_ERROR` `field: to`).
- 결과가 없으면 "이 기간에 그룹이 없습니다"를 표시한다.

## SCR-10. 채팅 보관함 (관리자)

```
┌─────────────────────────────────────────────────────────────────────┐
│ 채팅 보관함                                                         │
│ 삭제된 그룹의 채팅 내용입니다. 관리자만 볼 수 있습니다              │
├──────────┬──────────┬─────────────┬────────────────────────┬────────┤
│ 날짜     │ 그룹명   │ 메시지      │ 삭제 시각              │        │
│ 9/19(토) │ 연습C    │ 메시지 3개  │ 삭제 9. 20. 오전 10:02 │ [삭제] │
│ 9/12(토) │ 저녁반   │ 메시지 12개 │ 삭제 9. 13. 오후 11:40 │ [삭제] │
└──────────┴──────────┴─────────────┴────────────────────────┴────────┘
 9/19(토) 연습C   ← 고른 행의 대화, 읽기 전용
┌─────────────────────────────────────────────────────────────────────┐
│ 최민호(탈퇴) · 9. 18. 오후 08:00                                    │
│ (이번 주는 쉬어요)                                                  │
│ 박관리 · 9. 19. 오전 09:12                                          │
│ (이미지 메시지)                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

| 요소 | 동작 |
|------|------|
| 목록 | 삭제된 그룹 가운데 메시지가 있던 그룹만, 최근에 삭제된 순서로 보인다. 열은 날짜, 그룹명, `메시지 n개`, `삭제 {시각}`, [삭제]다(R-15) |
| 행 | 누르면(또는 Enter) 표 아래에 그 그룹의 대화를 `9/19(토) 연습C` 제목으로 읽기 전용으로 보여 준다. 고른 행은 옅은 보라 배경이다. 이미지는 SCR-03처럼 더블클릭 크게 보기와 오른쪽 버튼 내려받기를 쓸 수 있고, 글 복사는 없다. 탈퇴 회원은 실명과 `(탈퇴)`로 보인다(R-9) |
| 삭제 | 확인 창(제목 `보관된 채팅 삭제`, "{날짜 그룹명}의 메시지 n개를 삭제합니다. 되돌릴 수 없습니다", 예: "9/19(토) 연습C의 메시지 3개를 삭제합니다. 되돌릴 수 없습니다")을 거친 뒤 보관된 채팅을 지운다. 되돌릴 수 없다(R-15). 실패하면 토스트로 알린다 |

- 관리자 메뉴 `채팅 보관함`으로 들어간다. 관리자가 아니면 SCR-03으로 보낸다(R-8).
- 보관된 채팅이 없으면 "보관된 채팅이 없습니다"를 표시한다.
