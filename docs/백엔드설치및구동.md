# 백엔드 설치 및 구동

cal-todo 백엔드(Express 5 + PostgreSQL 17)를 로컬에서 설치하고 실행하는 방법이다. 근거: [5-project-principle.md](5-project-principle.md) C-1 ~ C-3, C-14, C-18, C-19, T-2.

## 1. 준비물

| 항목 | 버전 | 비고 |
| ---- | ---- | ---- |
| Node.js | 22 이상 | `package.json`의 `engines`. `--env-file`, `--watch` 내장 기능을 쓴다 |
| PostgreSQL | 17 | 개발용 `cal_todo`, 테스트용 `cal_todo_test` 두 DB |

## 2. DB 만들기

PostgreSQL에 접속해 두 DB를 만든다. 테이블은 서버가 기동할 때 마이그레이션으로 만들므로 직접 만들 필요가 없다(C-14).

```sql
CREATE DATABASE cal_todo;
CREATE DATABASE cal_todo_test;
```

## 3. 환경 변수 파일

`backend/.env`(개발·운영)와 `backend/.env.test`(테스트)를 만든다. 두 파일은 git에 올리지 않는다(`.gitignore`).

```dotenv
DATABASE_URL=postgresql://<user>:<password>@localhost:5432/cal_todo
JWT_ACCESS_SECRET=<32바이트 이상 무작위 문자열>
JWT_REFRESH_SECRET=<32바이트 이상, ACCESS와 다른 값>
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=<8자 이상>
PORT=3000
```

`.env.test`도 같은 키를 쓰되, `DATABASE_URL`은 반드시 `cal_todo_test`를 가리켜야 한다. 이름에 `_test`가 없으면 테스트가 DB에 닿기 전에 멈춘다(T-2).

| 변수 | 필수 | 설명 |
| ---- | ---- | ---- |
| `DATABASE_URL` | 예 | PostgreSQL 접속 문자열 |
| `JWT_ACCESS_SECRET` | 예 | 32바이트 이상. 짧거나 없으면 기동 실패 |
| `JWT_REFRESH_SECRET` | 예 | 32바이트 이상, `JWT_ACCESS_SECRET`과 달라야 한다 |
| `ADMIN_EMAIL` | 조건부 | DB에 영구 관리자가 없을 때만 필요. 첫 기동 때 이 값으로 영구 관리자를 만든다 |
| `ADMIN_PASSWORD` | 조건부 | 위와 같음. 영구 관리자가 생긴 뒤에는 쓰지 않는다 |
| `PORT` | 아니오 | 기본 `3000` |
| `NODE_ENV` | 아니오 | `production`이면 Refresh Token 쿠키에 `Secure`를 붙인다 |
| `ACCESS_TOKEN_TTL` | 아니오 | 기본 `15m`. 토큰 만료를 수동으로 확인할 때만 개발에서 줄인다 |
| `CORS_ORIGINS` | 아니오 | 다른 출처에서 API를 부를 때만. 쉼표로 구분한 허용 출처(예: `http://localhost:5173,https://app.example.com`). 비우면 CORS 헤더를 보내지 않는다 |
| `CHAT_IMAGE_MAX_BYTES` | 아니오 | 채팅에 붙여넣는 이미지 최대 크기(바이트). 기본 `2097152`(2MB) |

비밀키는 아래 명령으로 만든다. 두 번 실행해 서로 다른 값을 넣는다.

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

## 4. 설치

```bash
cd backend
npm install
```

운영 서버에서는 개발 도구를 빼고 설치한다.

```bash
npm ci --omit=dev
```

## 5. 구동

| 명령 | 용도 |
| ---- | ---- |
| `npm run dev` | 개발. 파일을 저장하면 자동으로 재시작한다(`node --watch`) |
| `npm start` | 재시작 없이 실행 |
| `NODE_ENV=production npm start` | 운영(쿠키 `Secure`). 운영 서버에서는 PM2(fork 1개)로 띄운다(C-19) |

기동 순서는 환경 변수 검증 → 마이그레이션 적용 → 영구 관리자 확인 → listen이다. 성공하면 다음 줄이 찍힌다.

```
cal-todo backend: http://localhost:3000
```

확인:

```bash
curl -i http://localhost:3000/api/nope
# 404 {"error":{"code":"NOT_FOUND",...}}
```

`ADMIN_EMAIL`·`ADMIN_PASSWORD`로 `POST /api/auth/login`을 호출하면 관리자 Access Token을 받는다.

## 6. 테스트

```bash
cd backend
npm test                                                          # 전체
node --env-file=.env.test --test --test-concurrency=1 test/auth.test.js   # 파일 하나
```

| 파일 | 내용 |
| ---- | ---- |
| `test/config.test.js` | 기동 실패(비밀키, 영구 관리자 설정) |
| `test/auth.test.js` | 가입·로그인·토큰 재발급·재사용 감지·로그아웃·내 정보 수정·로그인 시도 제한 |
| `test/attendance.test.js` | 그룹 생성 원자성, 참석·취소, 정원·중복 동시성 |
| `test/admin.test.js` | 관리자 권한, 회원 삭제, 그룹 편집·삭제, 탈퇴 회원 가림, 참석 현황·그룹 목록 |
| `test/cors.test.js` | CORS 허용 목록(`CORS_ORIGINS`) |

테스트는 매번 `cal_todo_test`의 모든 테이블을 비운다(`TRUNCATE`). 개발 DB를 `.env.test`에 넣지 않도록 주의한다.

## 7. API

모든 경로는 `/api` 아래다. 요청·응답 형식은 [backend/swagger.yaml](../backend/swagger.yaml)과 [2-PRD.md](2-PRD.md) 9장을 따른다.

| 영역 | 경로 |
| ---- | ---- |
| 인증 | `POST /auth/signup`, `/auth/login`, `/auth/refresh`, `/auth/logout` |
| 내 정보 | `GET`·`PATCH /me` |
| 캘린더·날짜 | `GET /calendar`, `GET`·`POST /dates/:date/groups`, `POST /dates/:date/attendance` |
| 참석 | `POST`·`DELETE /groups/:id/attendance`, `GET /attendance` |
| 관리자 | `GET`·`PATCH`·`DELETE /admin/members`, `GET`·`PATCH`·`DELETE /admin/groups`, `DELETE /admin/groups/:id/attendance/:memberId` |

로그인 외 API는 `Authorization: Bearer <accessToken>` 헤더가 필요하다. Refresh Token은 `refresh_token` 쿠키(`Path=/api/auth`)로 오간다.

### Swagger UI

개발 환경(`NODE_ENV`가 `production`이 아님)에서는 브라우저로 **http://localhost:3000/api-docs** 를 열면 API 문서가 보인다. 화면은 CDN(jsdelivr)에서 받으므로 인터넷 연결이 필요하고, 운영에서는 이 주소를 열지 않는다.

1. `POST /auth/login`을 [Try it out]으로 실행한다. Refresh Token 쿠키는 브라우저가 저장한다.
2. 응답의 `accessToken`을 [Authorize]에 넣으면 나머지 API를 호출할 수 있다.

### CORS

프론트엔드는 Vite 프록시(개발)나 같은 서버(운영)로 같은 출처에서 API를 부르므로 기본은 CORS가 꺼져 있다. 다른 출처에서 직접 부를 때만 `.env`의 `CORS_ORIGINS`에 그 출처를 적는다. 요청에는 `credentials: 'include'`를 넣어야 Refresh Token 쿠키가 오간다. 도메인이 다른 사이트에서는 쿠키가 `SameSite=Strict`라 재발급이 되지 않는다.

## 8. 기동 실패 시

서버는 listen 전에 `기동 실패: <이유>`를 찍고 종료한다(C-2).

| 메시지 | 조치 |
| ------ | ---- |
| `환경 변수 X가 없습니다` | `.env`에 해당 키를 넣는다 |
| `X는 32바이트 이상이어야 합니다` | 3장 명령으로 비밀키를 다시 만든다 |
| `JWT_ACCESS_SECRET과 JWT_REFRESH_SECRET은 달라야 합니다` | 두 값을 다르게 넣는다 |
| `영구 관리자가 없습니다. ADMIN_EMAIL과 ADMIN_PASSWORD를 설정하세요` | 빈 DB의 첫 기동이다. 두 값을 넣는다 |
| `마이그레이션 ... 실패` | DB 접속 정보와 DB 존재 여부를 확인한다 |

포트 충돌은 위 형식이 아니라 Node 오류(`EADDRINUSE`)로 나온다. 3000 포트를 쓰는 프로세스를 끄거나 `PORT`를 바꾼다.
