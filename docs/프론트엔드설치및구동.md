# 프론트엔드 설치 및 구동

Badminatics 프론트엔드(React 19 + Vite 8 + TypeScript)를 로컬에서 설치하고 실행하는 방법이다. 백엔드는 [백엔드설치및구동.md](백엔드설치및구동.md)대로 먼저 띄워 둔다. 근거: [5-project-principle.md](5-project-principle.md) C-3, C-18, L-9, ST-4.

## 1. 준비물

| 항목 | 버전 | 비고 |
| ---- | ---- | ---- |
| Node.js | 22 이상 | 백엔드와 같은 버전을 쓴다 |
| 백엔드 | 실행 중 | 기본 `http://localhost:3000`. `backend/.env`의 `CORS_ORIGINS`에 `http://localhost:5173`이 있어야 한다 |

주요 라이브러리: `react-router-dom`(화면 이동), `@tanstack/react-query`(서버 데이터), `zustand`(로그인 상태·언어·토스트).

## 2. 환경 변수 파일

Vite가 모드에 맞는 파일을 읽는다. 형식은 `frontend/.env.example`을 복사해 쓴다. `.env*` 파일은 git에 올리지 않는다(`.env.example`만 올린다).

| 파일 | 읽는 명령 |
| ---- | ---- |
| `frontend/.env.development` | `npm run dev` |
| `frontend/.env.production` | `npm run build` |

```dotenv
VITE_API_URL=http://localhost:3000/api
```

| 변수 | 필수 | 설명 |
| ---- | ---- | ---- |
| `VITE_API_URL` | 아니오 | 백엔드 API 주소(경로 포함, 끝에 `/` 없이). 개발 `http://localhost:3000/api`, 운영 예 `https://api.example.com/api`. 비우면 같은 출처의 `/api` |

- Vite 프록시는 쓰지 않는다. 개발에서도 브라우저(`http://localhost:5173`)가 백엔드를 직접 부르므로 백엔드 CORS 설정이 필요하다.
- 모든 요청에 `credentials: 'include'`를 넣어 Refresh Token 쿠키가 오간다. 쿠키의 SameSite 설정은 [백엔드설치및구동.md](백엔드설치및구동.md) 7장 "CORS와 분리 배포"를 따른다.
- `VITE_` 값은 빌드할 때 코드에 들어간다. 값을 바꾸면 개발 서버를 다시 띄우거나 다시 빌드한다.

## 3. 설치

```bash
cd frontend
npm install
```

## 4. 구동

| 명령 | 용도 |
| ---- | ---- |
| `npm run dev` | 개발 서버. **http://localhost:5173** . 파일을 저장하면 화면이 바로 바뀐다 |
| `npm run build` | 운영 빌드. 결과는 `frontend/dist/` |
| `npm run typecheck` | 타입 검사(`tsc --noEmit`) |
| `npm run lint` | ESLint(`eslint.config.js`) |

확인:

1. 브라우저로 http://localhost:5173 을 열면 로그인 화면으로 간다.
2. 백엔드 `ADMIN_EMAIL`·`ADMIN_PASSWORD`(또는 가입한 계정)로 로그인하면 이번 달 캘린더가 보인다.

## 5. 화면 주소

| 주소 | 화면 | 권한 |
| ---- | ---- | ---- |
| `/login`, `/signup` | 로그인, 회원가입 | 로그인 전(로그인 상태면 `/`로) |
| `/` (`?month=YYYY-MM`) | 캘린더 + 그룹 채팅 | 회원 |
| `/dates/:date` | 날짜 상세 | 회원 |
| `/attendance` (`?from&to&group&name&status&capacity`) | 참석 현황 | 회원 |
| `/me` | 내 정보 | 회원 |
| `/admin/members`, `/admin/groups`, `/admin/chats` | 회원 관리, 그룹 관리, 채팅 보관함 | 관리자(아니면 `/`로) |

그 밖의 주소는 `/`로 보낸다. 768px 이상은 데스크톱, 미만은 모바일 배치다. 모바일 확인은 브라우저 개발자 도구의 기기 모드(예: 390×844)로 한다.

## 6. 동작 참고

- **로그인 유지**: Access Token은 메모리에만 두고, 새로고침하면 Refresh Token 쿠키로 다시 받은 뒤 `GET /me`로 복원한다. 브라우저 저장소(localStorage)에는 언어 설정(`lang`)만 남긴다.
- **언어**: 한국어·English·中文. 처음에는 저장한 값, 없으면 브라우저 언어, 그것도 아니면 영어로 보인다. 상단 바와 로그인·가입 화면의 선택 상자로 바꾼다.
- **자동 갱신**: 캘린더와 그룹 채팅은 3초마다, 내 정보(역할 반영)는 30초마다 서버에서 다시 읽는다.
- **로그**: 콘솔 로그는 개발 모드(`npm run dev`)에서만 남고 운영 빌드에서는 남지 않는다.

## 7. 운영 배포

1. `frontend/.env.production`에 운영 백엔드 주소를 넣는다(`VITE_API_URL=https://api.example.com/api`).
2. `npm run build`로 `frontend/dist/`를 만든다.
3. `dist/`를 정적 파일 서버(웹 서버, 정적 호스팅)에 올린다. 화면 주소(`/dates/...` 등)를 새로고침해도 열리도록 없는 경로는 `index.html`로 돌려주게 설정한다.
4. 백엔드 `CORS_ORIGINS`에 운영 프론트엔드 출처를 넣는다. 다른 사이트(다른 상위 도메인)면 `COOKIE_SAME_SITE=none`과 HTTPS가 필요하다.

Express가 `dist/`를 함께 서빙하는 방식(같은 출처)은 아직 구현되지 않았다.

## 8. 문제 해결

| 증상 | 원인과 조치 |
| ---- | ---- |
| 로그인하면 아무 반응이 없고 콘솔에 CORS 오류 | 백엔드 `CORS_ORIGINS`에 `http://localhost:5173`을 넣고 백엔드를 다시 띄운다 |
| 새로고침하면 로그인이 풀린다 | Refresh Token 쿠키가 막혔다. 프론트·백엔드가 다른 사이트면 `COOKIE_SAME_SITE=none` + HTTPS. `/auth/refresh`가 403이면 출처가 `CORS_ORIGINS`에 없다 |
| 모든 요청이 `localhost:5173/api`로 간다 | `VITE_API_URL`이 비어 있다. `.env.development`를 만들고 개발 서버를 다시 띄운다 |
| `npm run dev`가 5173이 아닌 포트로 뜬다 | 5173을 다른 프로세스가 쓰고 있다. 그 프로세스를 끄거나, 바뀐 출처를 `CORS_ORIGINS`에 넣는다 |
