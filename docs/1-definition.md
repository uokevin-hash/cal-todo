## 번호 정책

- `REQ-n`(요구사항), `R-n`(규칙), `UC-n`(유스케이스)은 한 번 붙이면 바꾸거나 다시 쓰지 않는다. 새 항목은 마지막 번호 다음을 쓴다.
- 없어진 항목은 지우지 않고 `(폐기, vX.Y)`로 남긴다.
- 파생 문서(시나리오, 화면 설계서)는 머리말에 기준이 된 이 문서의 버전을 적는다.

## 1. 개요

- **목적**: 배드민턴 동호회 회원이 캘린더에서 날짜별로 운동 참석 여부를 등록하고, 조(그룹) 편성을 조회·관리한다.
- **문제**
  - 인증된 회원이 개인별로 날짜별 참석 여부를 관리할 수 있는 앱이 없다.
  - 참석 여부를 매일 등록하고 조회할 수 있어야 한다.

## 4. 핵심 엔티티

### 4.1 회원 (Member)

| 속성 | 타입 | 규칙 |
|------|------|------|
| id | ID | 시스템이 생성 |
| name | 문자열 | 필수 |
| email | 문자열 | 필수, 이메일 형식, 활성 회원 사이에서 중복 불가, 로그인 ID로 사용 |
| password | 해시 문자열 | 필수, 8자 이상·최대 72바이트, 해시로 저장 |
| phone | 문자열 | 필수, 휴대전화 형식 `01X-XXX(X)-XXXX`(하이픈 생략 가능, 숫자 10~11자리) |
| birthDate | 날짜 | 필수 |
| age | 정수(파생값) | 저장하지 않고 `현재연도 - 출생연도`로 계산 (예: 2026 - 1974 = 52). 기준 시간대는 R-12 |
| role | 열거형 | `MEMBER` \| `ADMIN`. 가입하면 `MEMBER`, 관리자가 바꿀 수 있다 |
| isPermanent | 불리언 | 영구 관리자만 `true`. 시스템 전체에 1개만 있다 |
| deletedAt | 일시 | 삭제된 회원이면 삭제 시각, 활성 회원이면 비어 있음(R-9) |

- 생년월일 표시 형식: `1974년11월14일(52세)`

### 4.2 그룹 (Group)

특정 날짜에 함께 운동하는 조.

| 속성 | 타입 | 규칙 |
|------|------|------|
| id | ID | 시스템이 생성 |
| date | 날짜 | 필수 (그룹은 날짜에 속한다) |
| name | 문자열 | 필수, 같은 날짜 안에서 중복 불가. 기본값 `기본` |
| capacity | 정수 | `2`(단식) 또는 `4`(복식/혼복)만 허용. 그룹을 만드는 사람이 지정하고, 관리자가 조정할 수 있다 |
| createdBy | FK → Member | 그룹을 만든 회원 또는 관리자 |

### 4.3 참석 (Attendance)

회원이 특정 날짜의 그룹에 참석하겠다고 등록한 기록.

| 속성 | 타입 | 규칙 |
|------|------|------|
| id | ID | 시스템이 생성 |
| memberId | FK → Member | 필수 |
| groupId | FK → Group | 필수. 지정하지 않으면 해당 날짜의 `기본` 그룹 |
| createdAt | 일시 | 등록 시각 |

### 4.4 관계

```
Member 1 ──< Attendance >── 1 Group (date, name, capacity)
```

## 5. 비즈니스 규칙

- **R-1 인증**: 가입과 로그인을 제외한 모든 기능은 로그인해야 쓸 수 있다. 삭제된 회원은 로그인할 수 없다.
- **R-2 그룹 생성**
  - 회원과 관리자 모두 날짜별 그룹을 만들 수 있고, 만들 때 정원(2명 또는 4명)을 지정한다.
  - 만든 사람은 기본적으로 첫 참석자로 등록된다. "참석하지 않고 만들기"를 고르면 그룹만 만든다.
  - 만든 사람이 그날 이미 다른 그룹에 참석 중이면 "참석하지 않고 만들기"만 할 수 있다(R-4).
  - **기본 그룹**: 참석을 등록할 때 그룹을 지정하지 않으면 해당 날짜의 `기본` 그룹에 들어간다. `기본` 그룹이 없으면 그 자리에서 만들며, 이때 등록하는 사람이 정원을 지정한다.
  - `기본`은 기본 그룹 전용 이름이다. 그룹을 만들 때 이름을 `기본`으로 할 수 없고(기본 그룹은 그룹 없이 참석할 때만 생긴다), 그룹 이름을 `기본`으로 바꾸거나 `기본` 그룹의 이름을 바꿀 수 없다.
- **R-3 정원**
  - 한 그룹의 참석 인원은 정원을 넘을 수 없다. 정원이 찬 그룹(`기본` 그룹 포함)에 참석하려 하면 거부하고 "정원이 가득 찼습니다"를 알린다.
  - 정원을 현재 참석 인원보다 작게 바꿀 수 없다.
- **R-4 중복 참석 금지**: 회원은 같은 날짜에 하나의 그룹에만 참석할 수 있다.
- **R-5 그룹 상태** (저장하지 않고 계산)
  - `참석가능`: 참석 인원 < 정원
  - `참석완료`: 참석 인원 = 정원
- **R-6 참석 변경 기한 없음**: 날짜에 제한 없이(지난 날짜 포함) 참석을 등록하거나 취소할 수 있다. 취소하면 해당 참석 기록을 삭제한다.
- **R-7 이력 보존**: 시스템은 참석·그룹 기록을 자동으로 삭제하지 않는다. 기록이 없어지는 경우는 참석 취소(R-6), 관리자의 참석자 제거(R-8), 회원 삭제 시 오늘 포함 이후 참석 정리(R-9), 관리자의 그룹 삭제(R-13)뿐이다. 지난 날짜의 기록도 조회할 수 있다.
- **R-8 권한**
  - 회원: 자기 정보 수정, 그룹 생성(정원 지정), 자기 참석 등록과 취소. 그룹은 자기가 만든 것도 삭제할 수 없다.
  - 관리자: 회원 권한 전부. 추가로 그룹 편집·정원 조정, 그룹 참석자 제거, 그룹 삭제(R-13), 모든 회원 정보 편집과 삭제, 관리자 지정·해제
  - 관리자의 회원 비밀번호 변경: 관리자는 현재 비밀번호 없이 회원의 새 비밀번호를 지정할 수 있다. 기존 비밀번호는 볼 수 없다(해시로만 저장). 영구 관리자의 비밀번호는 예외다(R-11).
- **R-9 회원 삭제**
  - 회원 정보(이름, 이메일, 전화번호, 생년월일 등)는 지우지 않고 남기며, `deletedAt`을 기록해 비활성화한다. 관리자는 회원 관리 화면에서 삭제된 회원의 정보를 볼 수 있다.
  - **오늘(R-12 기준)을 포함한** 이후 날짜의 참석 기록은 삭제한다. 어제까지의 참석 기록은 남긴다.
  - 그 회원이 만든 그룹은 날짜와 관계없이 남긴다.
  - 남은 기록(지난 참석 기록, 그 회원이 만든 그룹의 만든 사람)은 보는 사람에 따라 다르게 표시한다. 관리자가 아닌 회원에게는 이름 대신 `탈퇴 회원`으로, 관리자에게는 어느 화면이든 실명 옆에 `(탈퇴)`를 붙여 보여 준다. 관리자가 아닌 회원이 참석자 이름으로 검색하면 탈퇴 회원의 기록은 실명으로 걸리지 않는다.
  - 삭제된 회원의 이메일로 다시 가입할 수 있다. 새 회원으로 취급하며 지난 기록과 연결하지 않는다.
  - 관리자는 자기 자신을 삭제할 수 없다.
- **R-10 관리자 지정**
  - 관리자는 회원의 역할을 `MEMBER`에서 `ADMIN`으로, 또는 그 반대로 바꿀 수 있다. 관리자는 자기 역할도 해제할 수 있다.
  - 회원은 역할을 바꿀 수 없다.
- **R-11 영구 관리자**
  - 시스템이 시작할 때 영구 관리자가 없으면 1개 만든다. 이미 있으면 만들지 않는다.
  - 이메일과 초기 비밀번호는 배포 설정(환경 변수)으로 받고 소스 코드에 넣지 않는다. 설정이 없는데 영구 관리자도 없으면 시스템이 시작되지 않는다.
  - 삭제할 수 없고 `MEMBER`로 바꿀 수 없다. 따라서 관리자가 한 명도 없는 상태는 생기지 않는다.
  - 이메일과 비밀번호는 영구 관리자 본인만 바꿀 수 있다. 다른 관리자는 이름, 전화번호, 생년월일만 수정할 수 있다.
- **R-12 날짜 기준**: "오늘", 날짜 비교, 나이 계산의 "현재연도"는 모두 한국 시간(Asia/Seoul)을 기준으로 한다.
- **R-13 그룹 삭제**
  - 그룹은 관리자만 삭제할 수 있다. 날짜와 참석 인원에 관계없이 삭제할 수 있다.
  - 그룹을 삭제하면 그 그룹의 참석 기록을 모두 삭제한다. 참석자들은 그 날짜에 참석하지 않은 상태로 초기화되어, 다른 그룹에 다시 참석할 수 있다(R-4).
  - `기본` 그룹도 삭제할 수 있다. 이후 그룹 없이 참석하면 R-2에 따라 `기본` 그룹을 다시 만든다.

## 9. 용어집

| 용어 | 정의 |
|------|------|
| 그룹(조) | 특정 날짜에 함께 운동하는 모임. 정원은 2명 또는 4명 |
| 단식 | 정원 2명인 그룹 |
| 복식/혼복 | 정원 4명인 그룹 |
| 기본 그룹 | 그룹을 지정하지 않은 참석이 들어가는 날짜별 기본 그룹 |
| 참석가능 | 정원이 아직 차지 않은 그룹 상태 |
| 참석완료 | 정원이 모두 찬 그룹 상태 |
| 영구 관리자 | 설치 때 만들어지며 삭제하거나 해제할 수 없는 관리자 계정 |
| 탈퇴 회원 | 관리자가 삭제해 비활성화된 회원. 정보는 남아 있고, 관리자가 아닌 회원에게는 남은 기록에 이 이름으로 표시된다. 관리자에게는 어느 화면이든 실명과 `(탈퇴)`로 보인다 |
